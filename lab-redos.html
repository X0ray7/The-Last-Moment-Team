Regular Expression Denial of Service (ReDoS)

OWASP A04:2021 — Insecure Design CWE-1333

1 What it is

ReDoS happens when a regular expression contains nested quantifiers that force the regex engine into exponential backtracking on crafted input. A single short string can lock up a JavaScript thread or server CPU for seconds or minutes, denying service to other users.

2 The line

validator-vulnerable.js
1function validateCampusEmail(input) {
2 if (typeof input !== "string") {
3 return { valid: false, ms: 0 };
4 }
5 const start = performance.now();
6 const emailRegex = /^([a-zA-Z0-9]+)+@demo\.local$/; ← Vulnerable Line
7 const valid = emailRegex.test(input);
8 const ms = performance.now() - start;
9 return { valid, ms };
10}

Line 6 nests + inside another + (([a-zA-Z0-9]+)+). When the string ends with an invalid character like !, the engine tries 2n ways to split the letters before failing.

4 Why it matters

Node.js and web browsers execute JavaScript on a single main thread. If one request triggers catastrophic backtracking, the entire server or browser tab stalls, dropping legitimate traffic without needing a botnet.

Real-world incident: On July 2, 2019, a single backtracking regular expression deployed in a Cloudflare WAF rule spiked CPU usage to 100% globally and caused a 27-minute worldwide outage returning 502 errors.

5 The fix

validator-fixed.js
1function validateCampusEmail(input) {
2 if (typeof input !== "string" || input.length > 64) {
3 return { valid: false, ms: 0 };
4 }
5 const start = performance.now();
6 const emailRegex = /^[a-zA-Z0-9]+@demo\.local$/; ← Security Fix
7 const valid = emailRegex.test(input);
8 const ms = performance.now() - start;
9 return { valid, ms };
10}

Removing the nested quantifier makes matching strictly linear O(n). Switch to Fixed mode and run Attack 2 again to see execution drop below 0.1 ms.
