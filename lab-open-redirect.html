Open Redirect

OWASP A01:2021 — Broken Access Control CWE-601

1 What it is

An Open Redirect occurs when a web application takes a user-controlled URL parameter (such as ?redirect=...) and sends the browser straight to that destination without checking whether it belongs to the same site. Attackers abuse this flaw to craft links starting with a trusted domain that silently forward victims to a phishing page.

2 The line

redirect-vulnerable.js
1function handleLoginRedirect(queryString) {
2 const params = new URLSearchParams(queryString);
3 const nextUrl = params.get("redirect") || "/dashboard";
4
5 // Assumes nextUrl is always an internal route
6 if (!nextUrl.trim()) {
7 return navigate("/dashboard");
8 }
9 return navigate(nextUrl); ← Vulnerable Line
10}

Line 9 passes untrusted input directly to navigation without verifying the scheme or origin. Both full URLs (https://evil.example) and protocol-relative URLs (//evil.example) escape the application domain.

4 Why it matters

Email filters and security-conscious users inspect the start of a link to judge trust. Because an Open Redirect begins with a legitimate domain, victims trust the link and enter credentials on an attacker-controlled lookalike page, or leak OAuth authorization tokens.

Real-world incident: In OAuth 2.0 security advisories documented in RFC 9700 and OWASP CWE-601 reports, open redirect endpoints on trusted domains have repeatedly been chained with OAuth login flows to hijack authentication tokens and bypass phishing filters.

5 The fix

redirect-fixed.js
1function handleLoginRedirect(queryString) {
2 const params = new URLSearchParams(queryString);
3 const nextUrl = (params.get("redirect") || "/dashboard").trim();
4 const origin = "https://ghurir-portal.demo";
5
6 const parsed = new URL(nextUrl, origin); ← Security Fix
7 if (!nextUrl.startsWith("/") || nextUrl.startsWith("//") || parsed.origin !== origin) {
8 return navigate("/dashboard"); // Reject external hosts
9 }
10 return navigate(parsed.pathname + parsed.search);
11}

Switch the sandbox to Fixed mode and re-run Attack 1 or Attack 2 to verify both external and protocol-relative redirects are blocked.
